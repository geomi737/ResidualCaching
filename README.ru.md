# ResidualCaching

Экспериментальная архитектура **Causal Token Merging with Residual Caching** на базе [nanoGPT Андрея Карпаты / Andrej Karpathy](https://github.com/karpathy/nanoGPT).

Идея и направление проекта: **[geomi737](https://github.com/geomi737)**. В разработке помогали **Gemini** и **ChatGPT, включая Codex**. Спасибо Andrej Karpathy за nanoGPT, открытый код и образовательную работу. Исходная MIT-лицензия nanoGPT сохранена в `nanoGPT/LICENSE`.

## Как это работает

Первые `merge_layer` блоков обрабатывают полную последовательность. Затем завершённые окна из `R` токенов сжимаются:

```text
compressed = Σ softmax(weights)ᵢ · xᵢ + Σ xᵢ
```

Здесь `xᵢ` — контекстные представления после первых блоков. Сумма добавляется как residual-путь. Глубокие блоки работают с меньшим количеством позиций, а LM head предсказывает сразу из сжатых представлений. **Разжатия нет.**

Незавершённый хвост остаётся набором singleton-позиций. Для окна размера 1 та же формула даёт `C(x)=x+x=2x`; без residual-суммы получается `x`. Последовательности `[C,C,x]` корректны: каждый элемент предсказывает токен после последней исходной позиции, которую он представляет.

Если представить `[x₀,x₁]` одним вектором и вернуть его на позицию `x₀`, предсказание `x₁` уже будет содержать информацию об ответе. Поэтому прототип с unmerge оставлен только для истории и не используется в текущей causal LM.

## Обучение

Для сдвинутых таргетов `Y[t]=X[t+1]` выбираются индексы концов окон: `R−1, 2R−1, …`, плюс исходные позиции токенов хвоста. Получается примерно `T/R` обучающих предсказаний за один forward.

Длины батчей варьируются в диапазоне `max(1,B−R+1)…B`, чтобы обучать все доступные хвосты. Дополнительно `unmerged_prob=0.1` оставляет 10% батчей полностью singleton-последовательностями. Это обучает глубокие слои и на сжатом, и на несжатом контексте; первые блоки всегда видят полную последовательность.

## Запуск

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
cd nanoGPT
python data/shakespeare_char/prepare.py
python train.py config/train_residual_shakespeare.py
python sample.py --out_dir=out-residual-shakespeare
```

Команды для CPU, параметры, resume и benchmark приведены в [основном README](README.md).

## Что пока не доказано

- Сумма не сохраняет индивидуальные векторы без потерь. При равномерных весах на старте она лишь масштабирует среднее; преимущество для качества требует проверки.
- Постоянного KV-cache пока нет: каждый шаг генерации пересчитывает префикс. Слово caching здесь обозначает residual-агрегацию, а не уже реализованный кеш между шагами.
- Ускорение и снижение VRAM зависят от модели, доли ранних блоков, длины контекста и оборудования. CPU-проверки корректности не подтверждают эти преимущества.
- Сжатый loss покрывает меньше позиций. Benchmark сравнивает одинаковые validation-таргеты, но число обучающих предсказаний различается.
- После достижения `block_size` контекст обрезается, позиционные индексы и границы окон задаются заново относительно текущего префикса.
